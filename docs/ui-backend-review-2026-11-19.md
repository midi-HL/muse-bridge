# WebUI 与后端复查记录（2026-11-19）

基线：`b89a084` / v0.1.35。范围：全部自写 Go 后端生产源码，以及 `web/` 的当前页面、样式与交互。`.reference/` 是上游参照，未作为本轮自写代码审查范围。真实凭证和本机运行目录不进入仓库、CI 或本报告。

## 界面修复

- 所有页面采用同一垂直间距容器，列表、配置卡和测试面板之间保留独立间距；移除 grid 内相邻卡的额外 top margin。
- 固定应用外壳，只在主内容区滚动；聊天与日志由各自内容列表滚动，避免页面和内部列表双重滚动。保留窄屏表格必要的横向滚动。
- 统一筛选框、表单和聊天模型下拉框。支持 `appearance: base-select` 的浏览器使用主题内菜单；旧浏览器保留可访问的原生选择控件。
- 统一 favicon、侧栏标记和导航图标。顶部纯图标按钮不再挤入可见说明文字，保留可访问名称与悬停提示。
- 移除重复标题说明、侧栏宣传标签、聊天中重复模型选择和无数据的协议能力卡；成功结果详情默认折叠，保留明确错误和必要的凭证/人设提示。
- 修复主题切换重建聊天界面，以及首条消息后空态遮住消息列表的问题；发送中刷新保持停止按钮和当前流。

## 后端已确认并修复

| 问题 | 改动与回归边界 |
|---|---|
| Telegram 总开关与白名单开关未参与运行配置 | 开关参与配置比较、New/Reload 和会话绑定前过滤；开启但名单为空时不接收任何用户。兼容未显式提供新配置的包级调用 |
| Telegram 长流切分后尾段丢失 | 保存新发送尾段到 current，后续 delta/Close 不再覆盖或删除它 |
| Telegram 原始符号变成 HTML 实体 | 当前文本入口按纯文本发送/编辑，保持 `<>&` 与 UTF-16 分段；本次没有新增 Markdown 渲染器 |
| 完整 JSON 订阅事件绕过 1 MiB 限制 | 两处快速解码返回点均核对解码器 InputOffset |
| 首次管理员设密的并发覆盖 | 同一 Auth 实例的检查、写入及创建会话放在现有互斥锁中，只有一个首次设置成功 |
| CLI 不带 ID 的全池探活调用错误接口 | `accounts probe` 调用 protocol.probe，指定 ID 时仍为 accounts.probe，额外参数本地报错 |
| Windows 上失败导出残留空文件 | keys create / backup export 的失败路径先关闭输出句柄再清理，允许同路径重试 |
| 合法 URL Base64 ID 被拒 | managed ID 接受合法的 `-` / `_` 首字符，仍拒绝路径分隔符及点开头的路径名 |
| ASR 保存配置后仍使用旧 Processor | 与 settings 一并发布不可变 Processor 快照；读取使用相同设置锁，活动请求保留自身快照 |
| 备份恢复运行态未说明需重启 | 导入 account/settings 时返回 requires_restart，并在前端明确提示；不在活跃请求中替换账号池 |

三个独立审查分工覆盖 HTTP/认证/存储/CLI、Core/Pool、协议/Telegram/Media；修复后交叉复审各自未编写的补丁。前端复审发现的两项新回归均已修复并加入验证。独立审查结论只证明本轮可核验范围，不能解释为所有未来缺陷为零。

- 对旧源码使用 Go overlay 运行新增回归，记录修前失败；不回退共享工作区或接触运行数据。

## 仍保留的功能与实测边界

- Telegram 入站附件、生成物原生媒体回传、出站贴纸、真正的视频抽帧、视觉描述仍有原有未完成项，本轮没有扩写这些能力。
- 远端任务/会话/官方额度/远端取消仍按能力对照表处理；本地 `/usage` 不代表官方余额。
- 账号池尚不是完整的冷却与失败故障转移状态机；探活的通用错误不应直接解释为凭证失效。
- 本轮新账号实际连通、真实 Telegram 对话与真实媒体结果另行按观察记录，不能由合成页面或协议模拟测试代替。
