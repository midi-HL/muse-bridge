# 聊天输入区与账号状态修复（2026-11-20）

基线：v0.1.36 / `3e06aca`。本轮只调整聊天输入区、探活分类及其界面展示，保留现有账号、主密钥、管理员密码、Telegram 配置和人设选择语义。

## 输入区

- 移除 textarea 的方形焦点 outline；在整个 13px 圆角 composer 上显示焦点边框与阴影。附件和选择控件保留各自的焦点反馈。
- 回形针使用独立、可键盘操作的按钮，直接触发隐藏文件输入；更新图形并固定 34px 点击区。生成中按钮及文件输入同时禁用。
- 人设默认项缩短为“默认”，“无预设”缩短为“无”；模型、人设和发送按钮在同一行，选择框高度固定 34px，长名称单行截断，完整名称可悬停查看。
- 默认人设仍由服务器决定，前端不发送覆盖字段；已有服务器人设仍可选择。
- 修复停止一次生成后，下一轮停止按钮仍被禁用的问题。

## 账号探活

原账号池忽略 Hatch 探活的失败分类，统一保存为 `error / account probe failed`，使工作区未运行和认证失败在页面上看起来相同。现在保留固定诊断代码，不保存或转发上游原始响应：

| 实际分类 | 保存状态 | 界面含义 |
|---|---|---|
| pending_vm | pending_vm | 工作区未运行 |
| auth | invalid | Muse 账号认证失败 |
| network | error | Muse 连接失败 |
| protocol | error | Muse 协议响应异常 |

HTTP 将 `pending_vm` 映射为 503 + 固定错误码，前端普通请求和 SSE 使用相同的本地化提示。探活失败后刷新账号状态；停用账号优先显示“停用”。取消、超时和 generation 变化仍沿用原有保护，不覆盖新 Cookie 或配置。这里没有新增账号冷却/自动故障切换状态机。

## 本机真实连接诊断

四条旧导入记录与新 Cookie 的两种格式均单独验证。仅保留状态码、受限状态枚举和字段是否存在等信息；未记录 Cookie、VM ID、端点地址或原始响应正文。

| 输入记录 | session HTTP | 工作区状态 | wake HTTP | 有限轮询结果 |
|---|---:|---|---:|---|
| 旧记录 1 | 200 | UNKNOWN | 200 / wake_requested | 未进入 RUNNING |
| 旧记录 2 | 200 | DISABLED | 409 | 仍为 DISABLED |
| 旧记录 3 | 200 | DISABLED | 409 | 仍为 DISABLED |
| 旧记录 4 | 200 | DISABLED | 409 | 仍为 DISABLED |
| 新 Cookie 请求头 | 200 | UNKNOWN | 200 / wake_requested | 未进入 RUNNING |
| 新 Cookie JSON | 200 | UNKNOWN | 200 / wake_requested | 未进入 RUNNING |

所有 session 均返回 assigned，VM 与端点字段存在，未收到 401。当前有证据的阻塞点是工作区启动；这不能解释为 Cookie 全部已失效，也不能等同于真实聊天已经通过。DISABLED 的具体服务端原因没有在本轮推断。两份新导出仍作为同一账号，只导入一次，旧四条记录保持停用。
